Counting requests and answers protected against an answer arriving more than 15 s late, but rAthena never sends one. It handles the request as it arrives:
- it answers a refusal at once;
- it moves you without an answer on success;
- it never answers in a few cases (the feature switched off, a target map on another map server, an instance map).

So a lost answer is the case that happens, and it shouldn't hold up retries. Only one request is on its way at a time, and a map load still forgets it. Test: "frees the window as soon as a retry after a lost answer is answered". All 1354 tests pass.
